A ternary whose then-branch ends in `null`, `true`, `false`, `undefined` or `this` after an operator now compiles correctly. In `a ? b ?? null : c`, the lexer took `null :` for an object key and treated `null` as an identifier. Inside a class this compiled to `b ?? this.null`, which returns `undefined` when `b` is nullish. The same happened with `||`, `+`, `!` and the other operators. Keys after a binary operator, as in `a ?? null: 1`, are still object keys. You no longer need to wrap the operand in parentheses, as in `a ? (b ?? null) : c`.
