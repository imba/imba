Class flags with a literal condition, such as `<div .checked=yes>` or `<op-button .checked=no>`, are now set correctly. `.checked=yes` used to leave the class off until another flag on the element changed, and then added it with literal backticks in the class name; `.checked=no` was ignored. A true literal now works like a plain `.checked`, and `no`, `false`, `null`, `undefined` and `0` leave the flag out. The same applies to style flags such as `<div [c:red]=yes>`, which used to compile to invalid JavaScript.
