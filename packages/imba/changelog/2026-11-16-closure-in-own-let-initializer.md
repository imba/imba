A closure inside the initializer of a `let` now reads the variable that the `let` declares, as in JavaScript. Before, in a class or tag method, `let timer = setInterval(&, 1s) do clearInterval(timer)` compiled to `clearInterval(self.timer)`, so the interval never stopped, and `let walker = document.createTreeWalker(node, 1, acceptNode: do(n) check(n, walker))` passed `self.walker`. Only `let x = do ...`, where the closure is the whole initializer, read the variable. Now every closure in the initializer does, because a closure can run after the declaration.

Outside a closure, the initializer still reads self, so `let title = title` and `let items = items.map(do(i) i + 1)` read `self.title` and `self.items` as before. A closure that the initializer calls at once, such as `let n = list.find(do(v) v == n)`, now reads the variable, which has no value yet. Write `self.n` there if you mean the property.
