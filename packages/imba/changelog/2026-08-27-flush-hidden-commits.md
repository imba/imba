Flush queued commits while the document is hidden (dev builds). The scheduler ticks on `requestAnimationFrame`, which never fires in hidden tabs — so state changed in a background tab (live sync, automation-driven events, an async `mount` finishing after data load) left commits queued forever and `await imba.commit!` never resolved until the tab was fronted. When `imba.scheduler.flushHidden` is on (defaults to on in dev builds, off in production) a scheduled tick whose queue contains a commit now flushes through a `MessageChannel` — unlike timers, message ports are not throttled in background tabs — so hidden documents render within milliseconds. Ticks with no queued commit (raf listeners, animations) stay frozen as before; a commit landing within a frame of the last tick retries on a throttled timer, so a self-committing render loop cannot spin unbounded while hidden; and a `visibilitychange` hook flushes commits whose rAF callback was already parked when the tab hid. Production behavior is unchanged unless opted in with `imba.scheduler.flushHidden = yes`. The scheduler singleton is now also exposed as `imba.scheduler`, and a stale parked rAF callback (fired on refront after a hidden flush already ran its tick) is ignored instead of producing an extra tick.
