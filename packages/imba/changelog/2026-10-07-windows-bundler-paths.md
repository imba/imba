Fix three bundler problems on Windows. Asset urls in the manifest and in the generated html used `\` as the separator; in a JavaScript string the backslash became an escape, so a page that compared its asset urls with the server reloaded again and again. The urls now always use `/`. An external package that the build directory cannot reach (for example one in a nested `node_modules`) now gets an absolute path; the check for this looked for a `../` prefix, which a Windows relative path never has. In an esm build, an absolute external path is now a `file://` url, because the esm loader of node does not accept a drive letter in a specifier.
