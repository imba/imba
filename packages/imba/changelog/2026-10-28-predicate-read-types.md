The TypeScript-based tooling types a predicate read as the value it yields at runtime. A read (`doc.readable?`, `self.readable?`, implicit `readable?`, `super.readable?`) and a call without arguments (`doc.readable?!`, `doc.readable?()`) are typed as the getter's value or the method's return value. So `let ok\boolean = doc.readable?` no longer reports a false error, and neither does `doc.stopped?!` on a getter. Reading a method that has required parameters, like `doc.writable?` for `def writable? by`, reports `Expected 1 arguments, but got 0` on the read. The TypeScript output passes the member through a `ΦREAD` helper that the compiler declares at the end of each file that uses it, so the typings do not need to change.

Two tsc outputs that were not valid TypeScript are also fixed. `super.readable?` used to compile to `'readableΦ' in super`, and `new Doc().readable?` used to apply `new` to the predicate check.
