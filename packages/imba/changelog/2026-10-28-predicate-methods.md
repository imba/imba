Predicate identifiers work for getters and for methods with parameters alike. A `def` whose name ends with `?` and takes no parameters now compiles to a getter (in class bodies, tags, `extend class`, object literals and `def Foo.foo?` form), so `item.ready?` yields the value whether `ready?` was declared with `def` or `get`. Previously a `def ready?` made `item.ready?` evaluate to the function itself, which is always truthy. A predicate `def` with parameters is a regular method called with its arguments (`list.includes? item`), and no longer warns `Only getters/setters should end with ?`, so there is no need to rename such methods to `isIncludes` or `has-item` (#656).

An explicit zero-argument call (`item.ready?!` / `item.ready?()`) compiles to `typeof (t = item.readyΦ) == 'function' ? t.call(item) : t`. It reads the property once and calls it only if it is a function (a predicate field that holds a function, or code compiled by an older Imba), so callers never need to know which form was used. Plain property access stays a plain property access, with no runtime cost.

Two kinds of parameterless predicate `def` cannot become getters: generators, and functions declared outside a class or object. They stay plain functions, so a bare `ready?` refers to the function itself. The compiler warns about these and suggests calling them as `ready?!`.

Async predicates are supported. A `def ready?` or `get ready?` whose body awaits compiles to a getter returning the promise of an async arrow (`get readyΦ(){ return (async () => { ... })() }`), so `await item.ready?` works. This also replaces the invalid `async get` that any getter containing `await` used to emit. A promise is always truthy, so using an async predicate of the same class in a condition, operator or assignment without `await` (`if ready?`, `let x = ready?`, `<div .on=ready?>`) now warns at compile time. Awaiting it, chaining onto it (`ready?.then`), returning it or passing it along does not warn.
