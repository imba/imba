Predicate methods and getters are now interchangeable. A `def` whose name ends with `?` and takes no parameters compiles to a getter (in class bodies, tags, `extend class`, object literals and `def Foo.foo?` form), so `item.ready?` yields the value whether `ready?` was declared with `def` or `get` – previously a `def ready?` made `item.ready?` evaluate to the function itself, which is always truthy. Plain property access stays a plain property access, so there is no runtime cost. An explicit zero-argument call (`item.ready?!` / `item.ready?()`) now compiles to `typeof (t = item.readyΦ) == 'function' ? t.call(item) : t`, reading the property once and only calling it if it turned out to be a real function (a predicate declared with parameters, or code compiled by an older Imba), so callers never need to know which form was used. Predicate `def`s that take parameters or are generators cannot become getters; they stay regular methods and the old `Only getters/setters should end with ?` warning is replaced by one that says why and suggests an `is`-prefixed name. Async predicates are supported: a `def ready?` or `get ready?` whose body awaits compiles to a getter returning the promise of an async arrow (`get readyΦ(){ return (async () => { ... })() }`), so `await item.ready?` works – this also replaces the invalid `async get` that any getter containing `await` used to emit. Because a promise is always truthy, using an async predicate of the same class in a condition, operator or assignment without `await` (`if ready?`, `let x = ready?`, `<div .on=ready?>`) now warns at compile time; awaiting, chaining (`ready?.then`), returning or passing it along does not.
