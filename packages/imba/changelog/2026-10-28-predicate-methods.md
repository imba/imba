Predicate members behave like Ruby predicates. Reading a predicate member (`doc.readable?`, `self.readable?`, implicit `readable?` or `super.readable?`) always yields its value: a getter returns its value, and a method is called without arguments. So `def readable? by = me` works both as `doc.readable?` and as `doc.readable?(friend)`, and callers never need to know which form a predicate has. The read compiles to `typeof (t = doc.readableΦ) == 'function' ? t.call(doc) : t`, which evaluates the receiver once; an explicit `doc.readable?!` gives the same result. Previously a predicate read was a plain property read, so reading a predicate method gave the function itself, which is always truthy.

A predicate `def` with parameters is a regular method called with its arguments (`list.includes? item`), and no longer warns `Only getters/setters should end with ?` (#656). A `def` whose name ends with `?` and takes no parameters compiles to a getter (in class bodies, tags, `extend class`, object literals and `def Foo.foo?` form), as if it were declared with `get`.

Writing to a predicate member never calls it. Assignments, `=?` and the other set-if-changed operators, `||=` and other compound assignments, `++`/`--`, `delete` and two-way bindings (`<input bind=open?>`) work on the property itself, and field values passed in the init object (`new Doc(open?: fn)`) are stored, not called. There is no longer a way to get a predicate method itself through `doc.readable?`. If you passed one along as a callback, wrap it: `&.readable?(x)` or `do doc.readable?($1)`. A predicate field holding a function is called when it is read.

A parameterless predicate `def` outside a class or object stays a plain local function, so a bare `ready?` refers to the function itself. The compiler warns about it and suggests `ready?!`.

Async predicates are supported. A `def ready?` or `get ready?` whose body awaits compiles to a getter returning the promise of an async arrow (`get readyΦ(){ return (async () => { ... })() }`), so `await item.ready?` works. This also replaces the invalid `async get` that any getter containing `await` used to emit. A promise is always truthy, so using an async predicate of the same class in a condition, operator or assignment without `await` (`if ready?`, `let x = ready?`, `<div .on=ready?>`) warns at compile time. Awaiting it, chaining onto it (`ready?.then`), returning it or passing it along does not warn.

The TypeScript-based tooling still types a read of a predicate method without arguments as the method rather than its return value.
