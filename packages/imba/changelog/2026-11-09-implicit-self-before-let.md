The compiler now warns when a closure in a method reads a name through self because the variable of that name is declared further down. In a class or tag method, a bare name that is not declared yet is a property of self, so in `let a = do b!` followed by `let b = do 1`, `a` calls `self.b()`. The same lines in a top-level `def` call the local `b`. Two closures that call each other hit this, and the earlier one throws `self.b is not a function` when it runs. The warning is `` `b` is declared with let further down - here it reads self.b. Declare it above (`let b`) or write self.b ``. Declare the variable above the first closure (`let b`, then `b = do 1`) or write `self.b`. The name still resolves to self, so the output does not change.

Only a closure, or a parameter default of a closure, gets the warning, because a closure can run after the declaration. A use outside a closure runs before the declaration, while the variable has no value yet, so `let x = items` followed by `let items = …` reads `self.items` as before and does not warn. A `let` in a sibling block or in another closure does not warn either, because the use cannot see that variable wherever it is declared. A call of a local `def` that is defined further down in the method always warns, because JavaScript hoists the function and the call could have used it.
